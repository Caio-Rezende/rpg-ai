# 🎲 RPG-AI: Agentic TTRPG Simulation Framework

RPG-AI is a professional-grade framework for orchestrating AI-driven tabletop RPG experiences. It leverages a hierarchical agent architecture and the Model Context Protocol (MCP) to create a seamless, deterministic loop between a human Dungeon Master (DM) and a cast of AI-driven characters.

## 🚀 Architectural Overview

Unlike simple LLM chat-bots, RPG-AI implements a strict state-machine orchestration to prevent narrative drift and "AI hallucination" of game outcomes.

### 🏗️ Hierarchical Agent Structure

The system is divided into two primary agent layers:

1.  **Core Clarification Agent (The Orchestrator)**
    - Acts as the system's "input gate."
    - Performs **Context Validation**: Ensures the DM's prompt contains all necessary state information (active characters, location, and clear objectives).
    - If the input is underspecified, it halts execution and requests clarification, ensuring the simulation never proceeds on assumptions.

2.  **Character Agents (The Actors)**
    - High-fidelity personas that consume a "Turn Brief" generated by the Orchestrator.
    - Combines character-specific attributes (from `/content/characters`) with the current narrative state to generate authentic actions.
    - **Mechanical Intent**: Instead of simulating a roll, these agents output a deterministic dice request (e.g., `[4, 6, 1, 20]`) for the MCP layer.

### 🛠️ Deterministic Tool Execution (MCP Integration)

To ensure fairness and mechanical integrity, all randomness is delegated to an external **MCP Server**.

- **Protocol**: Model Context Protocol (MCP).
- **Tool**: `roll_dice(dice_set: list[int])`
- **Workflow**: $\text{Agent Intent} \rightarrow \text{MCP Request} \rightarrow \text{Deterministic Result} \rightarrow \text{DM Resolution}$.
- This separation of concerns ensures that the AI cannot "cheat" or arbitrarily decide the success of an action; it can only intend the action and request the roll.

## 🔄 The Agentic Loop

The game progresses through a five-stage deterministic cycle:

`DM Input` $\rightarrow$ `Context Validation (Core Agent)` $\rightarrow$ `Persona-Driven Action (Character Agents)` $\rightarrow$ `Deterministic Roll (MCP Server)` $\rightarrow$ `DM Resolution` $\rightarrow$ `Loop Back`

│   └── agent_core.md # The blueprint for the agentic loop
├── content/          # Ground-truth state templates
│   ├── characters/   # Persona definitions and attributes
│   ├── encounters/   # Scenario-specific constraints
│   └── locations/    # Environmental data and triggers
├── mcp-server/       # Implementation of the dice-rolling protocol
